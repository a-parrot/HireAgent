# 登录与权限设计

对应脚本：[08-auth-rbac.sql](./08-auth-rbac.sql)。目标 MySQL 8.4，新增 5 张表，无需修改现有招聘表。当前前后端已实现并默认启用登录拦截。首位管理员需在 backend 目录执行 `uv run python -m scripts.create_admin` 交互初始化，运行说明见 backend/README.md。

## 表与关系

| 表 | 用途 |
| --- | --- |
| auth_users | 登录名、显示名称、密码哈希、角色、启停状态和临时锁定 |
| auth_roles | 管理员 admin、招聘人员 recruiter、只读用户 viewer |
| auth_permissions | 13 个接口功能权限 |
| auth_role_permissions | 角色拥有哪些权限 |
| auth_sessions | 可过期、可退出和吊销的登录会话 |

一个用户一个角色，一个角色多个权限，一个用户允许多个设备会话。当前属于系统级功能权限：招聘人员可操作全部岗位；只读用户可查看全部岗位、简历原件和结果。暂不做“只看本人岗位”、部门或多租户数据隔离。

| 功能 | 管理员 | 招聘人员 | 只读用户 |
| --- | --- | --- | --- |
| 查看岗位、简历原件、评估、排期、历史 | 是 | 是 | 是 |
| 编辑岗位与规则，上传/移除简历 | 是 | 是 | 否 |
| 执行评估、人工审核、清理无效记录 | 是 | 是 | 否 |
| 自动排期、改期、取消预约 | 是 | 是 | 否 |
| 会议/通知操作 | 是 | 是 | 否 |
| 用户创建、角色分配、停用、重置密码 | 是 | 否 | 否 |

拥有会议/通知权限不等于自动获得具体外部动作授权，仍须按原流程预览并确认。

## 执行方式

1. 在 Navicat 选择 hireagent，打开 08-auth-rbac.sql；自定义库名先修改 USE。
2. 执行整个脚本，创建表并初始化角色、权限和关联关系。
3. 末尾查询默认应返回 admin=13、recruiter=12、viewer=5。已有额外权限时计数可能更多。
4. 不会创建应用用户。后续通过应用初始化命令，交互设置首位管理员密码并生成 Argon2id 哈希；不要手填明文、使用 SQL SHA2 密码或复用数据库 root 密码。

脚本 IF NOT EXISTS 不校正旧表。DDL 自动提交，后半部分的事务只覆盖初始化数据；失败后应检查实际建表结果。重复执行会补回默认角色授权，后续修改权限后不要将它当作日常同步脚本。不要同时执行此 SQL 和尚未实现的同结构 Alembic 迁移。

## 后续登录实现约定

- 使用随机 Cookie 会话，不额外引入 Redis。登录后生成至少 32 字节随机令牌，原令牌仅通过 HttpOnly Cookie 发送，数据库只存 SHA-256 摘要。密码采用 Argon2id 编码哈希，不能使用普通 SHA-256 保存密码。参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 与 [密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
- 生产 Cookie 使用 Secure、HttpOnly、SameSite=Lax、Path=/，不设置跨站 Domain；本地 HTTP 开发单独配置。写接口额外校验 CSRF 令牌及请求来源，csrf_token_hash 绑定当前会话。认证令牌不放 localStorage，不写日志。
- 每次请求检查会话未过期、未吊销、用户 active，查询当前角色权限；未登录返回 401，无权限返回 403。角色变更/停用立即生效，不仅依靠前端隐藏按钮。
- 建议默认绝对有效期 8 小时、空闲超时 30 分钟，可通过配置修改；last_seen_at 节流更新，不能延长绝对过期时间。退出吊销当前会话；改密/重置吊销全部旧会话，成功改密后可重新签发当前会话。
- must_change_password=true 时仅允许本人信息、修改密码、退出等必要认证接口，不开放招聘业务。管理员重置密码后重新要求修改；禁止公开注册、用户自行修改角色，保护最后一个有效管理员不被停用或降权。
- 登录失败计数与 locked_until 在事务内更新，建议连续 5 次失败临时锁定 15 分钟；同时按来源限制登录频率，未知用户与密码错误返回同一提示，不透露账号存在性。会话定期清理过期记录，不使用数据库触发器。

## 接口和页面接入顺序

先实现 POST /api/auth/login、GET /api/auth/me、POST /api/auth/logout、POST /api/auth/change-password，以及仅管理员使用的用户管理接口，再增加全局登录依赖与各路由的权限依赖。登录和必要的最小健康检查可匿名；简历原件/预览、导出、历史正文、工作流重试和外部动作接口也必须鉴权。生产文档页关闭或鉴权。

前端增加登录页和路由守卫，根据 /auth/me 返回的权限显示按钮；遇到 401 返回登录，403 明确提示无权限。服务端才是权限判定依据。建立首位管理员后再启用强制登录，避免无法进入系统。

人工审核、岗位发布、会议授权的操作者改由服务端读取登录用户，不能信任前端传入的 operator_name。现有姓名字段保留历史兼容，新审计事件在 details 写入 actor_user_id、actor_username 与当时显示名称，由服务端生成，不覆盖旧记录。用户以停用代替物理删除，保留追溯信息。本轮不回填历史操作者，也不修改原业务表结构。
