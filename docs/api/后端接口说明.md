# HireAgent 后端接口与交接

精确请求结构以同目录 openapi.json 和运行时 /docs 为准。ID 响应为十进制字符串，请求路径和表单接受整数文本。错误统一使用 HTTP 状态码与 `detail`；404 不存在，409 版本或预约冲突，422 请求结构错误。模型/外部平台未配置或失败不伪造业务成功。

## 岗位

| 方法与路径 | 请求与行为 |
| --- | --- |
| GET /api/jobs | page、page_size，返回 items/total |
| POST /api/jobs | name、responsibilities、requirements、draft_rules；创建草稿 |
| GET /api/jobs/{id} | 草稿及 versions，发布版本包含完整 rule_snapshot |
| PATCH /api/jobs/{id} | 必须携带 draft_version，其他字段按需更新 |
| POST /api/jobs/{id}/publish | draft_version、operator_name；校验发布并推进草稿版本 |
| POST /api/jobs/{id}/disable | 停用，历史结果可查 |

规则格式示例位于 backend/app/conf/initial_job.json：hard_conditions 采用 all/any 树，叶子为 id/description/evidence_requirement；dimensions 是任意数量的维度，包含 id/name/max_score/criteria/evidence_requirement；review_threshold、recommend_threshold 定义分流；sort_priority 以 total_score 开始，其后引用有效维度并全部 desc；最终候选人 ID 升序。发布校验叶子和维度 ID 唯一、上限合计 100、阈值合法及受保护属性。已发布版本不可直接修改。

## 简历与批次

| 方法与路径 | 请求与行为 |
| --- | --- |
| POST /api/batches | multipart：job_id、rule_version_id、files（可重复文件字段）、可选 name |
| GET /api/batches | page/page_size，历史批次列表 |
| GET /api/batches/{id} | 批次快照及 progress、total |
| POST /api/batches/{id}/run | 202，幂等启动；重复返回 already_started=true |
| GET /api/candidates | 必填 batch_id；可选 status/recommendation/page/page_size |
| GET /api/candidates/{id} | 原始事实、条件、评分、证据、缺失风险、复核意见、审核历史、预约和动作 |
| GET /api/files/{id} | 原件 application/pdf；前端可用查看器按页码定位 |
| POST /api/candidates/{id}/retry | 202，仅失败状态允许，从失败节点继续 |

候选人不跨批次合并，文件按哈希复用；每批同文件只导入一次。POST 创建新批次用于显式重评，不把相同上传的所有新批次合并。上传列表中的同一文件不重复产生候选人；格式无效会拒绝本次上传，损坏但具 PDF 头的文件可导入后单独解析失败。文件写入与数据库 COMMIT 不确定时保留可能被引用的原件，不自动清理；需要定期核查未引用文件。

processing_status：pending/running/waiting_review/completed/failed。recommendation：recommended/needs_review/deferred，可为空。批次 evaluation_done 表示没有 pending/running，仍可有待审核或失败者，不代表通知完成。

## 人工审核与恢复

POST /api/candidates/{id}/review：

```json
{
  "operation": "approve",
  "review_version": 0,
  "reason": "已核对相关项目与证据",
  "operator_name": "招聘人员",
  "supplements": [{"description": "补充说明", "source": "人工面谈记录"}]
}
```

operation 为 supplement/approve/defer；补充必须有 description/source，不会自动批准。版本取候选人详情当前 review_version。保存决定后返回审核记录，resume_status=pending 表示恢复已排队，不能把它显示为恢复已完成；刷新候选人详情查看 succeeded/failed。重复决定或过期版本 409，失败恢复可通过候选人 retry 继续，不重复写审核决定。人工决定不覆盖模型分数与证据。

## 时段、排期与动作

| 方法与路径 | 请求与行为 |
| --- | --- |
| GET/POST /api/batches/{id}/slots | 查询或逐个添加实际时段，每批四个 |
| PATCH/DELETE /api/slots/{id} | 未预约时段可修改或删除，已预约 409 |
| POST /api/batches/{id}/schedule | 评估稳定后统一排序，仅有效批准者，满额候补 |
| GET /api/batches/{id}/schedule | reservations、waitlist |
| GET /api/reservations/{id}/action-preview | 预约、候选人、时段、动作及配置状态 |
| PUT /api/reservations/{id}/action-preview | preview_version、recipient、content；保存新版本并清除旧授权 |
| POST /api/reservations/{id}/approve-actions | preview_version、operator_name；批准后执行当前快照 |
| POST /api/reservations/{id}/retry-actions | 必须仍有有效授权；只重试未成功动作 |
| POST /api/reservations/{id}/reconcile-actions | 查询平台核实 running/uncertain；无法核实保持原状态 |

时段请求示例：starts_at=`2030-01-01T09:00:00+08:00`，ends_at=`2030-01-01T09:45:00+08:00`，timezone=`Asia/Shanghai`，可选 interviewer。调用时使用真实约定日期；示例日期不是预置时段。

当前 MeetingClient/NotificationClient 尚无具体平台实现，配置标记为 false；批准动作后仍会明确返回 not_configured，不创建真实会议或发送通知。需要用户选定平台后实现客户端 create/send/query，并进行授权对象上的真实验收。现有测试替身只验证编排，不属于产品后备服务。

## 日志、导出与状态

- GET /api/batches/{id}/events：after_id 游标及 limit，返回 items/next_cursor。
- GET /api/batches/{id}/export?format=json：包含批次及完整逐人记录，证据保留原文片段与页码。
- GET /api/batches/{id}/export?format=csv：UTF-8 BOM、动态维度列、复杂对象 JSON 摘要及公式前缀处理。
- GET /api/health 与 /api/health/ready：存活与数据库连通检查。

CSV 和 JSON 是当前查询时的数据视图，不锁定整批结果。需要归档时，在业务停止变更后导出并与 PDF 原件一并保管。

服务是单进程后台任务运行方式：通过 MySQL 命名锁拒绝第二个后端实例；成功节点输出和 LangGraph 检查点共同支持恢复。排期使用单进程日历锁和数据库事务/唯一约束；不得绕过应用直接修改预约表。跨批次同面试官时间冲突同样检查。

## 恢复与动作核实补充

后端启动会重新计算已启动批次的稳定状态，修复“最后候选人已落库但批次状态未提交”的重启窗口；不会自动批准等待人工的候选人。命名锁释放失败时仍关闭检查点上下文。

平台查询超时继续保持 uncertain，不自动重发。具体平台适配器 query 只有明确确认幂等动作未执行时，才能返回 `{"confirmed_absent":true}`；后端将其标记 failed，仍需显式 retry 才重新执行。查询确认成功时返回真实 external_id 与 status=succeeded。所有动作开始、成功、失败、未配置和待核实事件写入 events。
