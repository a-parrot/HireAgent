# HireAgent 分阶段开发提示词总览

本目录用于指导 AI 分步开发，并非三个业务智能体的运行时提示词；运行时提示词保存在 backend/app/prompts/。

当前起点：FastAPI、MySQLClient、配置、健康检查与基础测试已实现；业务迁移、岗位功能、招聘图和前端功能待开发。真实 Ubuntu 数据库尚需在目标环境验证。以下状态只表示任务安排，不代表功能完成。

## 使用方式

1. 按数字顺序打开阶段文件，将完整内容发送给开发 AI。先验收前置任务，再开始依赖任务。
2. 前序接口及验收记录是下一阶段的输入；AI 应核对实际实现，而非照文档猜测。
3. 每项包含实现、必要测试和交接说明；AI 报告完成后先标“待验收”，审查与验证通过才标“已完成”。
4. 当前串行开发。WorkBuddy 如参与必须遵守 AGENTS.md，不通过其他渠道重复派发，不自动处理其权限请求。
5. 初版只生成开发文档；本轮已按用户最新指令依次实施后端，前端暂缓。当前状态以同目录验收记录为准，已有 img.png 保留不变。

## 里程碑

- T01–T04：岗位规则与可操作管理页面。
- T05–T09：真实 PDF 到三智能体评估结果。
- T10–T12：批量执行、人工暂停恢复与结果审核页面。
- T13–T15：统一排期、真实会议通知、日志与完整导出。
- T16：全量需求验收及 Ubuntu 部署交付。

模型平台在 T07 前确定；会议与通知平台在 T14 前确定。凭证只填入本地环境配置，不写入任务提示词。初始化岗位规则属于配置，不是硬编码候选人输出。用户要求的自定义岗位、版本、证据、审批、并发、恢复、候补、幂等、日志及导出均纳入任务。

T01/T05/T10/T11/T13/T14 分别增量建立所属数据结构，避免一次预建全部表后反复改动。T07–T09 可先独立验证节点，T10 再串联；三个角色共享一个图，避免复制多个状态体系。

## 验收记录规范

在同目录的验收记录中按任务追踪：状态、实现范围、变更文件、接口及配置变化、执行命令和实际结果、证据路径、未解决问题、后续依赖。状态使用“待开始 / 进行中 / 待验收 / 已完成 / 受阻”。不能只凭 AI 自述或 reported_complete 判完成。

数据库设计已提供于 [backend/sql](../../backend/sql/README.md)，各阶段按此基线实现对应 ORM 与迁移。初始化 SQL 不等于已完成 T01，也不得在已导入库中重复运行不匹配的建表迁移；具体接入方式见 SQL 说明。

后端实现与限制已更新至 [验收记录](./验收记录.md)，各任务的原始“待开始”列仅为初始规划，不是当前验收结论。
