## 工作流文件规划

以下为文件职责说明；招聘工作流已实现，具体外部平台适配待选定。

| 计划位置 | 作用 |
| --- | --- |
| `app/main.py` | FastAPI 应用工厂与应用入口；backend/main.py 仅负责调用 Uvicorn 启动同一应用 |
| `app/agents/recruitment_agent/recruitment_graph.py` | 顺序连接节点、条件路由、人工中断 |
| `app/agents/recruitment_agent/recruitment_state.py` | 候选人共享 State |
| `app/services/workflow_service/runtime.py` | MySQL 检查点初始化、连接生命周期与后台恢复 |
| `app/services/resume_service/resumes.py` | PDF 文本与页码 |
| `app/agents/recruitment_agent/nodes/analysis.py` | 简历分析智能体 |
| `app/agents/recruitment_agent/nodes/analysis.py` | 岗位评估智能体 |
| `app/agents/recruitment_agent/nodes/analysis.py` | 评估复核智能体 |
| `app/agents/recruitment_agent/nodes/summarize_result.py` | 求和、结论与人工复核标记 |
| `app/services/workflow_service/runtime.py` | 暂停及审批后恢复 |
| `app/clients/mysql_client.py` | SQLAlchemy 连接池与会话 |
| `app/clients/llm_client.py` | 模型请求与结构化输出 |
| `app/clients/meeting_client.py`、`notification_client.py` | 外部请求及真实返回值 |

提示词计划命名为 `resume_analysis.prompt`、`candidate_evaluation.prompt`、`evaluation_review.prompt`。三个智能体共用一个招聘图，内部准备、调用和整理步骤不额外拆图。

## 职责边界

API 接收请求并调用 services；services 负责规则、批量调度、审核恢复、排序排期和外部动作编排；repositories 负责业务表读写；clients 封装外部连接。节点调用业务服务或客户端并更新 State，避免路由中直接调用模型或操作数据库。

统一排期由 schedule_service 在批次层执行，三个智能体仍按候选人顺序运行。检查点由适配器独立管理，业务仓储不手写检查点表。

与参考项目的区别：将 `respositories` 拼写规范为 `repositories`；不引入知识库检索、向量库、MinIO 或 MinerU。保留 uv、MySQL 迁移、Ubuntu Compose 和招聘所需原件存储。API 前缀保持技术方案定义，物理目录变化不改变接口契约。

后端已实现岗位、简历、三智能体工作流、审核、排期、导出及外部动作编排；具体会议/通知平台待选，模型权限及真实 MySQL 验收仍待解决。前端目录保持未开发。详见 docs/prompts/验收记录.md。
