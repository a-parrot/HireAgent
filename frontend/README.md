# HireAgent 前端

当前“已批准自动排期”不再以推荐分数线限制人工批准记录：人工批准面试后，即使原始分数为 40/60 分、原 AI 结论仍为需复核或不推荐，也可按总分降序自动安排。同分继续按岗位配置的排名优先级及候选人 ID 排列。填写起始时间后每人生成 45 分钟；已有预约保留且幂等。不再等待同批其他简历完成，也不等待已保存人工决定的工作流恢复锁。未批准的存疑结果仍不自动放行；原有评分达标且证据完整的自动准入规则保留。


登录权限已接入：未登录访问业务页会进入登录页，首次登录/重置密码后强制改密；右上角提供当前用户、角色、修改密码与退出。管理员在“用户管理”创建账号、分配角色、停启用、重置密码和吊销会话。只读账号隐藏写按钮，后端独立执行权限校验，不能靠直接请求绕过。

登录 Cookie 由后端写入，HTTP 客户端自动为写请求附带 CSRF 令牌；401 返回登录、无页面权限显示明确提示。账号由管理员创建，不开放注册，无预置账号密码；首次账号通过 backend 的 scripts.create_admin 初始化。密码和认证令牌不存 localStorage。开发依旧使用 Vite /api 同源代理。


人工操作流程：顶部依次进入“配置岗位 → 导入评估 → 审核结果 → 安排面试”，当前位置高亮，步骤均可点击。简历评估负责导入与重新评估，评估管理按“待人工审核 / 待安排面试 / 已排期 / 不推荐”切换，姓名下显示岗位，右侧突出下一步操作。失败记录显示查看重试或缓存恢复，未准入记录不展示排期操作。

审核详情先显示结论、分数和操作说明，再核对硬条件与匹配评分原文；顶部审核按钮滚动时保持可用，内容导航可定位硬条件、评分和审核记录。模型版本、节点等处理信息默认折叠。人工批准后才显示排期入口；审核提交期间表单禁用并避免误关闭。面试排期显示面试人数、已安排和待安排人数；空列表提供返回评估结果入口。窄屏自动收起侧栏，得分分组可横向滚动，表格在容器内滚动。

验证：前端构建及 9 项浏览器用例通过，新增覆盖阶段筛选、对应下一步操作、未准入不展示排期、处理信息折叠、768px 无页面横向溢出及面试列表返回待安排筛选。接口使用模拟数据，不执行真实审核或排期。

当前详情页显示硬条件内容、判定及对应原文；明确不合格时显示“不推荐 / 未进入评分”和未满足的条款原因。评分结果显示评分项名称、得分/配置分值、给分理由及原文，不再只显示内部 ID。评估管理列表也显示硬条件淘汰原因，“未评分”包含硬条件淘汰与技术失败，两者执行状态分别展示。

HireAgent 招聘评估系统的 Web 前端，基于 Vue 3 + TypeScript + Vite + Element Plus + Pinia。

## 启动

```bash
npm install
npm run dev
```

开发服务器运行在 http://localhost:5173 ，`/api` 请求通过 Vite 代理转发到后端 `http://127.0.0.1:8000`（后端启动命令见 `backend/README.md`）。后端 CORS 已允许 5173 来源，代理与非代理方式均可使用。

生产构建：

```bash
npm run build      # 类型检查 + 打包
npm run preview    # 本地预览构建产物
```

## 页面与功能

| 页面 | 路由 | 功能 |
| --- | --- | --- |
| 岗位管理 | `/jobs` | 默认加载已有岗位、名称搜索、状态筛选、可视化创建草稿/直接发布、编辑、启停、删除 |
| 岗位详情 | `/jobs/:id` | 修改名称、职责和规则；硬条件列表、匹配评分内容与分值、总分筛选阈值；草稿保存、版本发布及历史快照 |
| 简历评估 | `/resumes` | 岗位列表及已解析数量；单份/批量 PDF 导入、SHA-256 校验与去重反馈、解析状态、失败重试、原件/文本/评估详情、移除；直接开始评估、查看评估状态/得分/结论/详情、失败重试 |
| 候选人详情 | `/candidates/:id` | 硬性条件、维度评分、事实与证据（新证据查看解析正文，历史页码证据仍可定位原件）、缺失字段/风险/复核意见、审核历史、人工审核（补充/批准/暂缓 + 补充说明列表）、失败重试、排期与动作状态 |
| 面试排期 | `/schedules`、`/schedules/:batchId` | 时段管理（每批 4 个、固定 45 分钟）、统一排期、预约与候补列表、动作预览编辑（保存新版本清除旧授权）、批准/重试/核实动作 |
| 执行日志 | `/events/:batchId` | after_id 游标分页、加载更多、5 秒自动增量刷新、事件详情查看 |

## 约定与注意

- 后端 ID 响应为十进制字符串，前端类型定义（`src/api/types.ts`）全部按字符串处理。
- 审核决定保存后 `resume_status=pending` 表示恢复已排队，页面提示等待刷新确认，不显示为已完成。
- 会议/通知平台未配置时，批准动作会返回 `not_configured`，页面明确展示该状态，不伪装成功。
- 时段时间按本地时区生成带偏移的 ISO 字符串（如 `+08:00`），时区固定提交 `Asia/Shanghai`。
- 批次评估中每 5 秒轮询批次进度与候选人列表；批次完成后轮询自动停止。

## 岗位管理

每个岗位分别保存规则。规则表单分为“硬条件”和“匹配评分”两部分。硬条件仅编辑内容并增删；匹配评分逐行填写内容、分值并增删，总分实时展示，推荐/复核阈值置于评分区域。未完成的规则可保存草稿，发布时检查基本完整性及合计 100 分。开始评估时选择已发布版本后，后端按该版本快照自动组装智能体提示词。

删除前需确认；删除岗位隐藏列表入口并禁止新建批次，历史版本、批次与结果保留。停用后仍可编辑草稿，重新启用后可发布或用于新批次。后端旧数据库需先升级 jobs.deleted_at，见 backend/README.md。

## 界面风格

参照 `E:/lingxi/gitcodes/zhongyue-knowledge/frontend` 的企业后台风格：220px 深蓝灰侧栏（可收起为 64px）、56px 白色顶栏、蓝色主色 #2563eb、浅灰背景 #f0f2f5、6px 圆角与轻阴影。统一令牌定义于 src/styles/main.css，导航与响应式布局定义于 src/layouts/MainLayout.vue；岗位规则表单沿用相同配色。保留 HireAgent 品牌和招聘业务功能。


简历导入在后端通过 PyMuPDF 本地提取全文，当前前端默认连续完成解析和评分。删除仅移除当前岗位关联，原件和历史评估保留。前端每 5 秒更新状态，保留当前勾选；详细节点进度保存于服务端。浏览器处于 HTTPS 或 localhost 时同时计算上传哈希，其他 HTTP 来源仍由服务端计算并核对原件完整性。


简化规则表单保留原后端 JSON 契约，无需修改数据库。旧条件组在一行中以“且/或”展示，未编辑时保留原结构和条件 ID；编辑组合条件后以新单条内容保存。旧证据要求、未编辑评分标准和有效排序配置保留，删除评分项时清理其排序引用。修改评分内容会同步更新 name/criteria，使智能体使用当前内容；历史发布快照保持不变。


## 统一评估入口

已移除独立评估批次列表、详情及上传创建入口，旧 /batches 和 /batches/:id 网址转到 /resumes。用户在简历评估页面选择岗位、导入并解析简历，勾选后确认规则版本即可开始评估；无需创建或命名批次。列表展示最新评估状态、得分、结论和结果入口。候选人详情保留审核、失败重试、执行日志和单人 JSON/CSV 导出。

评估请求携带 request_id，同一请求重发不会重复建记录或调模型；每次主动发起新的评估使用新的请求标识。历史版本、候选人结果及排期不删除，底层 batches 作为执行/规则快照/排期关联保留，不提供独立批次管理界面。本轮不涉及数据库升级。


当前只接收 PDF。解析详情展示整份 Markdown 原文，不按页展示；本地解析任务进度保存在服务端。新证据使用正文来源标识和引用片段，结果页“查看来源”打开完整解析正文。旧页码证据和旧解析记录继续可读。已解析文件可确认“重新解析”后在后端本地更新全文，不调用解析云服务。


## 网络失败与状态刷新

开发端口固定为 5173（strictPort=true），被占用时明确报错，不自动切换到 5174；后端代理仍指向 127.0.0.1:8000。旧端口页面需要关闭并打开 http://localhost:5173/resumes。

简历页面完成一次轮询后再等待 5 秒开始下一次，后台刷新不会与未完成的列表请求重叠；搜索、切换岗位或手动刷新会取消旧列表请求。超时与连接失败分别提示。列表已有数据时刷新失败会明确显示“上次成功加载的数据，状态可能不是最新”，保留数据并提供重试连接入口；此时禁用开始评估，避免把旧状态当作新结果。

## 统一解析评估与按 Agent 组织（2026-11-15）

当前前端使用一次“导入并评估”：绑定已发布岗位规则，后台连续完成 本地全文解析、事实提取、评分和阈值分流。达到推荐阈值且硬条件与证据完整者自动进入面试队列；临界分数或信息不足者才调用复核 Agent，再等待人工确认；明确不达标者结束。没有可用面试时段时进入候补。自动准入在 Review/Event 中明确记录“系统自动分流”，不冒充人工决定。

Agent 代码按职责拆分：resume_evaluation_agent 统一负责 PDF 导入、分析、评分、分流与二次复核；interview_agent 保存面试准入与统一排期。recruitment_agent 仅保留总图、共享 State 和历史导入兼容。技术运行时继续负责检查点、并发、持久化、恢复和人工中断。

导入任务与评估任务共享解析缓存和进度，不重复执行同一活动解析。评分请求保留 request_id 幂等；相同内容重复导入不会自动创建另一份已有评估。完成后统一排序排期，不让并发候选人抢时段；重启恢复会补做已完成评估的排期。会议与通知继续使用原有预览和人工授权接口。

无需 SQL 迁移。旧审批记录、页证据和中断工作流保留；旧代码导入路径只作兼容，新实现位于各 Agent 目录。具体模型/会议服务的真实端到端验收不由隔离测试代替。

## 评估管理

侧栏“评估管理”对应 /evaluations；简历评估页也可带当前岗位直接进入。分组卡片展示全部、高分、临界、低分及无有效得分，阈值取每条评估的规则快照，兼容不同岗位与规则版本。支持岗位、姓名/文件名、最低/最高分及待审核、已准入、候补、已排期等状态筛选；相同最低/最高分可查看某一个分数的简历。

默认每份简历显示本岗位最近一次已结束评估，可勾选“包含历史评估”。点击简历或“人工审核”打开侧栏，保留完整事实、分项分、证据和批准/暂缓/补充功能；“排期管理”打开当前记录的时段、预约、候补和动作预览管理。审核和排期后刷新当前列表，保留筛选位置。高分信息不足仍需审核；历史原始评分不因人工决定被覆盖。无数据库迁移。

浏览器测试 tests/evaluations.spec.ts 覆盖评分组切换、精确分数过滤、高分待审核、侧栏批准和统一排期，API 均为模拟响应。

## Agent 目录合并与节点拆分（当前实现）

import_agent 已并入 resume_evaluation_agent，导入图和 ImportState 位于该目录。所有节点实现移到各自 Agent 的 nodes/<节点名>.py，不再集中在 agent.py 或 Runtime 的节点名称分支中；各运行时只负责通用调度、事务、进度、审计和恢复。招聘图节点名称与输入输出未改变，保留既有 MySQL 检查点和历史日志兼容。完整目录与职责见 backend/app/agents/README.md。

当前最终保留三个 Agent：recruitment_agent 负责总编排与人工中断；resume_evaluation_agent 合并原导入/复核职责，负责解析、分析、评分、分流与二次复核；interview_agent 负责面试准入与排期。每个节点继续独立保存于所属 Agent 的 nodes/ 下，原检查点节点名称及日志记录保持兼容。详见 backend/app/agents/README.md。

## 高分自动排期与无效数据清理

评估管理新增“高分自动排期”：未勾选记录时处理当前岗位（或全部在招岗位）的符合条件高分结果，勾选后只检查这些记录。使用已配置的未来可用时段；证据不足、待复核、技术失败及已删除记录不会自动准入；无时段进入候补。添加或修改可用时段后自动安排已准入候补，预约幂等；会议/通知仍须独立预览与授权。

列表支持单条删除和勾选批量删除无效评估，提交前明确确认。已准入面试、已有预约或运行中的记录受到保护。删除从业务列表隐藏，原件、解析历史、检查点及审计日志保留；审核和重试不能恢复已删除记录。当前页勾选期间暂停背景轮询，避免用户选择被刷新清除；操作后重读列表。后端使用现有 events 保存删除标记，不需要 SQL 迁移。未通过开发工具清理任何真实记录。

## 按起始时间生成自动排期（当前默认）

评估管理点击“高分自动排期”，填写北京时间起始时间和可选面试官。从指定起点连续生成每人 45 分钟的时段，按高分及规则优先级分配，已有预约不移动，面试官冲突自动顺延。取消原四时段限制；超过四位候选人也可生成。重复提交保留既有预约，不重复占位。新增时段/预约有独立审计事件，会议与通知仍需授权。

前端必填起始时间，接口保留未传 starts_at 时使用已配置时段的兼容模式。时间按 UTC 保存、Asia/Shanghai 展示；无 SQL 迁移。生成是连续安排，每人 45 分钟。

## 审核状态与缓存恢复

评估管理将“评估执行”和“人工审核”分列，技术失败不再显示为人工审核失败。评分已完成但 human_review 交接失败时显示“待恢复审核”，点击“恢复待审核”复用已保存节点结果，不重新调用模型；成功后显示“评分完成 / 待人工审核”。解析或模型失败显示“尚未进入审核”，从简历评估原重试入口处理。需先重启后端加载二进制检查点兼容修复，页面不会自动重试旧失败记录。


## 自定义排名优先级

在岗位规则的“匹配评分”下方配置“排名优先级”。总分固定第一，点击“添加排名项”从当前岗位评分项中选择，使用上移/下移调整同分比较顺序，也可删除；预览实时显示完整顺序。每项均为高分优先，字段不可重复；删除评分项时自动移除其排名项，改名后同步更新显示，内部仍使用稳定 ID。发布后新评估绑定该顺序，排期读取规则快照，分数完全相同时按候选人记录 ID 升序。旧版本和已有预约不自动重排。仅保存草稿不会改变已有发布版本，无需数据库迁移。

验证：构建、5 项规则测试、岗位/排名两项浏览器测试以及后端两项排序测试通过。浏览器验证增删、选择、上移、名称同步、删除评分项联动、保存重载和旧版本不变；后端验证自定义同分顺序、总分优先和稳定兜底。
